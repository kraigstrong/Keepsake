# Phase 8 — URL Import Foundation

**Result:** Pass | **Date:** 2026-08-05 | **PR:** [#26](https://github.com/kraigstrong/Keepsake/pull/26)

16 commits on `phase-8-url-import` — the first PR whose migration/pgTAP suite (`import_jobs` schema, RLS, rate-limit guards) ran for real in CI and passed, plus a live end-to-end import through the *deployed* Edge Function (real Wikibooks page, zero hallucination) and live SSRF-rejection checks against `169.254.169.254`/`127.0.0.1`. A genuine physical-device build was also done, though not required for this phase (ADR-0003).

ADR-0015 resolved the phase's design questions before writing pipeline code: the Edge Function uses the caller's own JWT (never the service-role key) for every Supabase read/write, so RLS stays the real enforcement boundary instead of a second, harder-to-audit authorization path — the only genuinely new server-only secret this phase needs is `ANTHROPIC_API_KEY`. The SSRF-hardened fetcher validates DNS on every redirect hop (not just the origin), with the DNS-rebinding TOCTOU gap named as a residual risk rather than assumed closed (closing it needs raw socket control, deliberately deferred). `import_jobs` is a synchronous-request bookkeeping table for this phase's in-app URL-entry flow, not a queue — Phase 9's Share Extension is what structurally needs one, per `docs/risk-spikes/durable-import-submission.md`'s own framing. Phase 1's `extractRecipe.ts` risk-spike code runs *unchanged* inside the Deno Edge Function (imported via relative path) since it only ever used Web-standard APIs — one implementation, Jest-tested in Node, Deno-executed in production.

`server/import/` (all pure, all independently unit-tested, all written with only Web-standard APIs so they run unchanged in both Jest and the Deno function): `normalizeUrl.ts` (canonicalization + the duplicate-detection key), `reduceHtmlToText.ts` (regex-based content reduction — no HTML-parsing dependency exists in this project, and a well-scoped pass handles typical recipe-blog markup adequately), `secureFetch.ts` (IP-literal rejection, DNS-resolve-then-validate, byte/timeout/content-type limits), `extractHeroImageUrl.ts` (og:image-first, `<img>` fallback). `supabase/functions/import-recipe/index.ts` wires it all together: normalize → duplicate-check (before any fetch or AI call) → fetch → reduce → extract → category/tag mapping → hero image acquisition (best-effort) → `save_recipe`. Extraction defaults to `claude-sonnet-5` (developer decision mid-session, after a live Opus-only call came in around 6 cents) and escalates to `claude-opus-5` only when the primary result's `title`/`ingredientSections`/`instructionSections` themselves come back uncertain or structurally empty — timing/yield/category uncertainty alone doesn't trigger the extra call, since a recipe with fuzzy timing is still fully usable.

Client: `src/import/` (API wrapper emitting timing-only telemetry, `ImportRecipeScreen`), wired into the global Add sheet and `app/recipe/import`. Two real bugs found during live device testing and fixed same-session: `ToastProvider`/`useToast` existed fully built and unit-tested since Phase 2 but had never actually been mounted anywhere in the real app tree; and every `recipe/*` route was missing an explicit `title` option, so React Navigation's back-button label and the OS app-switcher screenshot label fell back to the raw file-based route pattern — `app/recipe/_layout.tsx`'s `headerTitle: () => null` only hides the in-body header text, not the string title those two things need. Both fixed; the import flow now lands on the recipe detail screen with a confirmation toast ("Recipe imported" or "Already in your library" for a duplicate) and sensible navigation chrome.

A `security-check` pass (run before opening the PR, not after) found one real gap against this phase's own stated scope: execution-plan.md explicitly lists "Rate limits and cost controls" for Phase 8, and nothing had been built — a compromised or scripted client calling the Edge Function directly (bypassing the UI's own disabled-while-importing button) could spam real Anthropic spend or repeatedly exercise the SSRF fetcher. Fixed: `create_import_job` gained the same two-guard pattern already established for invitations (Phase 3) — a 5s cooldown and a 30-per-rolling-hour cap per household — with pgTAP covering both guards plus the boundary case that jobs outside the 1-hour window don't count against the cap. Also tightened the hero-image fetch's accepted content-types from a blanket `image/*` to the exact three the Storage bucket allows.

IMP-01, IMP-07, AI-01 through AI-08, IMG-01 → `Done (tested)`. ORG-04 shares AI-06's status: real, but a known, honestly-disclosed reliability gap — category mapping is exact-string matching against an 11-value seeded vocabulary Claude is never told about, so it works when the AI's free-text guess happens to coincide (confirmed working in live testing) rather than by robust design. Worth a follow-up passing the real category list into the extraction prompt. 67 suites, 447 passed, 1 skipped; typecheck/lint/format clean; `npm audit --omit=dev --audit-level=high` exit 0; the new `check:client-secrets` script (the Phase 0 "no server credential in client bundle" check, deferred until this phase actually added a real Edge Function) passes and is wired into both CI and the pre-commit hook.

Verification went well beyond Jest this phase: a real end-to-end live import (an actual Wikibooks recipe page) correctly extracted title/timing/yield/ingredients/instructions/tags with zero hallucination through the *deployed* Edge Function, not a local mock. The SSRF fetcher was verified live too — real requests to `169.254.169.254` (cloud metadata) and `127.0.0.1` both correctly rejected by the deployed function, not just Jest's injected-resolver tests. A genuine physical-device build was done (not Simulator) — found and fixed two real, unrelated native-toolchain issues along the way (a stale CocoaPods project referencing a moved vendored-source file, and a stale global Clang module cache holding a compiled `expo-sqlite` module from before the right preprocessor flags applied), neither specific to this phase's own code, both now resolved for future device builds on this machine too.

**Pass**, not Conditional Pass — developer judgment call (2026-08-05) that live-deployed-function verification plus a real device build were sufficient; two low-severity items (DNS-rebind TOCTOU residual risk in the SSRF fetcher, ORG-04's exact-string category mapping working by coincidence rather than robust design) are honestly disclosed and tracked in `docs/roadmap.md`'s Not-yet-triaged list, not blocking.
