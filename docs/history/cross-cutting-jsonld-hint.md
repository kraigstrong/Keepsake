# JSON-LD Structured-Data Import Hint (ADR-0019)

**Result:** Merged | **Date:** 2026-08-06 | **PR:** [#32](https://github.com/kraigstrong/Keepsake/pull/32) — cross-cutting, not a numbered phase

Developer-flagged gap, 2026-08-06: `reduceHtmlToText` (Phase 8, ADR-0015 decision 6) unconditionally strips `<script>` tags, discarding schema.org Recipe JSON-LD that most recipe blogs carry alongside their visible content. Not previously evaluated or rejected — just never built — and explicitly out of scope for the Phase 11 units/scaling work underway on its own branch when it was noticed.

ADR-0019 resolved the design question of how far to lean on it: JSON-LD becomes a sanitized text hint prepended to what Claude already sees, never a bypass of the AI extraction call — prd.md §8 documents one workflow ("Page reduced to relevant text → AI parses → Uncertainties highlighted → Save") for every URL import, and a full bypass for "complete-looking" structured data would silently change that contract plus reintroduce category/tag inference and reconciliation logic Claude's own extraction already does.

New `server/import/extractJsonLdHint.ts` (pure, Web-standard APIs only, following the existing `server/import/*.ts` pattern): finds a `Recipe` node (top-level, in a top-level array, or nested in `@graph`), flattens `recipeInstructions`' several legal shapes (string / array of strings / `HowToStep` / `HowToSection`), parses ISO 8601 durations, and sanitizes + length-caps every field (500 chars/field, 100 items/list, 4000 chars total) before formatting a labeled plain-text block — treated exactly as untrusted as the rest of the page (threat-model.md T17, same mitigation class as T5: the hint only ever becomes more prompt input, never a second path into `save_recipe`). `supabase/functions/import-recipe/index.ts`'s URL path prepends this hint to `reduceHtmlToText`'s output when present, and now also attempts extraction (rather than failing at the 200-char minimum-useful-text gate) when a thin-content page still carries real JSON-LD underneath — a real pattern on JS-rendered sites that still server-render structured data for SEO. No changes to `RecipeExtractionSchema`, the extraction prompts, or the Sonnet/Opus escalation logic — the hint is just better input to an unchanged call.

22 new Jest tests (`extractJsonLdHint.test.ts`) cover `@graph`/array-`@type`/top-level-array Recipe discovery, all four `recipeInstructions` shapes, ISO 8601 duration parsing (including unparseable-duration honesty), HTML/entity sanitization, malformed-block skip-and-continue, and every length/count cap.

No PRD IDs owned (strengthens AI-01/05/06/08's existing reliability, isn't a distinct requirement); no schema, RPC, or telemetry changes. Received a Codex review pass before merge (entity RangeError, scalar instructions, expanded type IRI — addressed). Not yet verified with a live Anthropic call (needs the developer watching, per this project's live-API-test convention) — Jest evidence only at merge time, same category every other `server/import/*.ts` module started in before its first live/staging exercise.
