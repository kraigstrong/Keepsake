# Phase 6 — Offline Read Model and Synchronization

**Result:** Pass | **Date:** 2026-08-03 | **PR:** [#23](https://github.com/kraigstrong/Keepsake/pull/23)

22 commits on `phase-6-offline-sync` — the first PR in this repo's history where a real CI run of the migration/pgTAP suite is confirmed (previously only ever reasoned about, never executed in this sandbox), and the first phase with genuine, if informal, physical-device/Simulator verification behind it (several real bugs found and fixed live).

ADR-0013 resolved the design questions the phase's build scope leaves open before any schema or client code exists: local SQLite mirrors the client's already-flattened `Recipe` read shape (one row per recipe, JSON columns for sections/tags/categories) rather than the server's normalized child tables, since nothing local ever queries into ingredients/instructions independently; sync cursor is `(updated_at, id)` / `(deleted_at, id)` tuples, not bare timestamps, to avoid missing or double-fetching same-instant changes; tombstones are a narrow `deleted_recipes(id, household_id, deleted_at)` table populated by a `before delete` trigger on `recipes` — forward plumbing added ahead of Phase 16's delete feature, which doesn't exist yet.

`src/db/` (SQLite schema + `PRAGMA user_version`-based migration runner) → `src/sync/`: `remote.ts`/`local.ts`/`syncEngine.ts` implement paginated initial+incremental pull, committing the cursor after every page (not just at the end) so an interrupted sync resumes rather than re-fetching or losing progress. `imageCache.ts` downloads and caches hero images with byte-budget (100MB) LRU eviction; the sync engine pre-caches each changed recipe's hero image right after upserting it, best-effort, so images are ready before a user might go offline. `ConnectivityProvider` (NetInfo-backed) wires the existing (Phase 2, never-actually-used) `OfflineState` banner into `app/_layout.tsx` and triggers `syncHousehold()` on mount and on reconnect. `LibraryScreen`/`RecipeDetailScreen` switched to local-first reads (`offlineRecipes.ts`) — a failed background sync no longer surfaces as an error, since that's the whole point of OFF-01; a failed *local* read still does. Sign-out now wipes the entire local SQLite file and cached-image directory (`wipeDatabase()`, `ImageStore.deleteDirectory()`), not a per-household filtered delete, since MVP was one household per user at the time (ADR-0004) — later revised by ADR-0020/Phase 11.5 once a real cross-account risk on shared devices was identified.

Two real bugs found and fixed along the way: `expo-sqlite`'s hooks module unconditionally imports `expo-asset`, which `expo` itself lists as a dependency but was never actually installed — nothing had previously imported `expo-sqlite` in a test (`src/search/search.ts` has used it since Phase 1, but only its pure query-building logic had coverage). And `@react-native-community/netinfo`'s real native module crashed every test that renders the real app tree, fixed with `__mocks__/@react-native-community/netinfo.js` re-exporting the package's own official jest mock (same convention as the existing `@sentry/react-native`/async-storage mocks).

One finding documented, not fixed: `expo-sqlite`'s default database location is inside the backed-up Documents-directory-equivalent, not the (correctly-excluded) cache directory hero images use — see ADR-0013's "Backup implications" section. Judged low-severity (a rebuildable server mirror, no credentials) and not attempted blind, since the fix needs on-device verification of a path-format mismatch between `expo-sqlite`'s default and `expo-file-system`'s `Directory.uri`. Tracked in `docs/roadmap.md`'s Security & Privacy Readiness backlog.

OFF-01 → `Done (tested)`. OFF-02 unchanged (Phase 7's search feature doesn't exist yet to test against); OFF-04's connectivity boundary was preserved by construction (editing/`save_recipe` untouched, still requires connectivity) but not given its own dedicated test. 53 suites, 287 passed, 1 skipped; typecheck/lint/format clean; `npm audit --omit=dev --audit-level=high` exit 0. No live device verification this phase specifically — done on the developer's own machine mid-session for the Phase 5.5 auth work, but Phase 6's sync/offline paths themselves haven't been clicked through on a real device yet (only Jest evidence).

**Pass**, not Conditional Pass — developer judgment call (2026-08-03) that the extensive live device/Simulator testing this session, though informal rather than a scripted walkthrough, was sufficient evidence; no follow-up required.
